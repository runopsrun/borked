# Borked OS agent rules

`PLAN.md` is the build contract. Do not switch the project to Arch, atomic, Anaconda, or a custom kernel unless that file is changed first.

- Do not disable SELinux, `gpgcheck`, or Secure Boot shim.
- Do not add packages except through `packages/include.list`.
- Do not vendor Fedora package payloads.
- Do not hand-edit `packages/lock`. Change the lists and run `just lock`.
- Dev builds stay `VARIANT=Development` and unsigned. The dev signing key is generated under `out/keys/` and is gitignored.
- Branding RPMs are built with `rpmbuild` inside `quay.io/fedora/fedora:${RELEASE}`. That container is the pinned Fedora release. Do not build them on the host.
- `just` is the entry point: `lock`, `root`, `iso`, `qemu`, `test`, `check`, `convert`.
- When a change affects the image, the installer, `convert.sh`, the package lists, or a command a person runs, update `README.md` and this file in the same change. Update `PLAN.md` only when the build contract itself changes.
- After image or installer changes, `just qemu` or `just test` is the definition of done. A script that exits 0 without a booted VM is not done.
- Rootless podman on this machine cannot `losetup`. `just root` uses rootful podman (`sudo podman --privileged`). Do not drop `btrfs send` because of that.
- v1 is x86_64 UEFI. The ISO is a hybrid image so it can boot BIOS and UEFI. The installed disk is UEFI: ESP plus btrfs, shim copied to `EFI/BOOT/BOOTX64.EFI`.
- Fedora identity packages (`fedora-release-identity-*`) are excluded because they own `/usr/lib/os-release`. `borked-release` provides `fedora-release-identity` at the same EVR as `fedora-release-common`.
- The installer still runs `setfiles` after the bootloader step. If the host kernel is older than the image policy and `setfiles` fails only with `Invalid argument`, continue. That is the F44-host / F45-image case for `just qemu`. Do not turn SELinux off to paper over it.

This file is the project memory. A new agent does not have the chat that produced it. Read this before changing the image, the installer, or the name.

## Decisions already made

`PLAN.md` is still the build contract. These later decisions override it where they disagree. Do not "fix" them back.

- The displayed name is **Borked**. `PRETTY_NAME` is `Borked`. The site is https://projectborked.com/. Copy should sound like that site: short, snarky, and willing to admit something is slightly broken. `PLAN.md` still says "Borked OS". Leave that file alone. Do not put "OS" back on the installer, the splash, or os-release.
- The console logo is three lines, centered on the top row of the splash, the installer, and `borked apps`. The B is `█▀█` / `█▀█` / `█▄█`: a top bar, two bowls, and a bottom bar. A two-line B has no caps, so the word reads as DORKED. The D is `█▀▄` / `█ █` / `█▄▀`. B and D must not use the same glyphs. The color runs left to right from `#b01058` through the brand `#ff3d81` to `#ffd0e8`. On the Linux console that ramp is palette slots 2, 10, 3, 11, 9, 1, 5, 13, 6, and 14. Bold selects the bright slot, so the splash does not add a second bold. Slot 9 is the brand pink and the bold red the menus use. A 256-color terminal recolors slots 16–25 for the same stops and resets them when `borked apps` exits. The splash is `iso/live-init`. The same logo is in `installer/borked_install/tui.py` and `apps/borked_apps/tui.py`.
- Default software goes in `packages/include.list`, then `just lock`. Something a group pulled in that must not ship goes in `packages/exclude.list`. Optional software is not in the base image. It is a line in `apps/catalog`, installed later with `borked apps`. New `borked` subcommands belong in `apps/borked_apps/`. The voice lines live in `apps/borked_apps/voice.py`. Cisco Duo is the `duo` catalog line (`duo_unix` plus `duo_unix-selinux` from Fedora). After install, `borked duo` writes `/etc/duo/login_duo.conf` as `sshd:root` mode 0600 and can drop `ForceCommand /usr/sbin/login_duo` into `/etc/ssh/sshd_config.d/50-borked-duo.conf`. Do not vendor Duo Desktop RPMs; Fedora's duo_unix is the path.
- Third-party RPM repos are `repos/*.repo`: `gpgcheck=1`, priority 110 so Fedora wins a name collision. `image/lib.sh` copies them in. Do not vendor their payloads.
- Flathub is the full remote from `repos/flathub.flatpakrepo` (`https://dl.flathub.org/repo/`). Do not switch it to Fedora's filtered `fedora-flathub-remote`.
- The COSMIC Flatpak remote is `repos/cosmic.flatpakrepo` (`https://apt.pop-os.org/cosmic/`), added system-wide beside Flathub. Applets such as YapCap are published there, not on Flathub. Do not drop the remote, and do not turn off its GPG verification.
- The top bar is Quickshell, from Fedora's `quickshell` package. `cosmic-session` always starts `cosmic-panel`; that process stays. `cosmic-panel` owns `/usr/share/cosmic/com.system76.CosmicPanel/v1/entries`. The image overwrites it with `["Dock"]` from `branding/cosmic-panel-entries`, and `borked-defaults` has a file trigger that writes the same list back when that directory changes. Do not put `Panel` back in that list, and do not take ownership of the file in an RPM. The dock stays. The bar config is `/usr/share/borked/quickshell/shell.qml`, started by the user unit `borked-quickshell.service` (`WantedBy=cosmic-session.target`). `shell.qml` sets `//@ pragma IconTheme Cosmic` and the unit sets `QS_ICON_THEME=Cosmic`, otherwise Qt uses `hicolor` and every status glyph is a magenta checkerboard. The bar floats in three pills. The right pill is sound (PipeWire), Bluetooth, network, battery when a laptop battery is present, the system tray, Agents, and power. Those status icons open one control center. Scroll changes the volume and a right click mutes. `bluez` and `upower` are in the image because the desktop group does not pull them, and `bluetooth.service` is enabled. This Quickshell build only exposes Wi-Fi devices, so the network chip also reads `nmcli` for a wired link. The Agents button is the slot. It does not read provider quotas yet.
- `wine-core` and `wine-filesystem` are installed in their own transaction with scriptlets off, then `/usr/bin/wine` is pointed at `wine64`. Fedora's `wine-core` 11.20 script registers the `d3d8` DLL under the `dxgi` alternative name and fails the whole rpm transaction. Do not drop Wine, and do not turn those scriptlets back on. The earlier glibc/bash bootstrap and the `generic-release` removal in `image/build-root.sh` are there because a single large transaction runs `crypto-policies` `%pre` before `/bin/sh` exists. Do not collapse the install back into one `dnf` transaction.
- The public package repo is not hosted yet. `specs/borked-repos.spec` still points at `https://repo.borked.invalid/`. Do not publish the Borked repo from COPR, and do not set `gpgcheck=0` to get a package in. COPR is an upstream we consume (Zed, Herdr, Hyprland via `nett00n/hyprland`), not where Borked publishes.
- The golden image always has `@cosmic-desktop` and a Hyprland stack from `repos/hyprland.repo`. The greeter stays `cosmic-greeter`; both `COSMIC` and `Hyprland` appear under `/usr/share/wayland-sessions/`. The installer asks which desktop to open by default and writes that name into `/var/lib/cosmic-greeter/.config/cosmic/com.system76.CosmicGreeter/v1/users` as `last_session` for the new user’s UID. Hyprland users also get `/usr/share/borked/hypr/{hyprland,hyprpaper}.conf` copied into `~/.config/hypr/`. Do not drop COSMIC to make Hyprland fit, and do not replace the greeter with SDDM.
- `out/` is gitignored. It holds the ISO, the stream, and the dev signing key. A new machine generates its own dev key on the first build. Never commit a private key.
- GitHub's check workflow belongs in the repository-root `.github/workflows/`, with commands run from `borked/`. It runs `just check`, not the VM acceptance checks. The root `LICENSE` covers original source under MIT; bundled fonts keep their own licenses. Optional `script` apps execute mutable vendor installers as the user, including any downstream downloads; do not describe them as pinned or signature-verified.
- `convert.sh` (`just convert`) turns a Fedora COSMIC install of the pinned release into Borked. It builds the branding RPMs in the Fedora container and installs them on that machine. It is not a second image installer. It does not disable SELinux or `gpgcheck`, and it does not wipe home. Its messages are snark. The error still names the real reason.
